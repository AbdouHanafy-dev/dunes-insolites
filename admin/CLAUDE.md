# Backoffice (`admin/`) — what to know before editing

Supplements the root [`../CLAUDE.md`](../CLAUDE.md). `AGENTS.md` above is
regenerated by `next dev` — put project knowledge here, not there.
Current scope and gaps: [`../docs/PROJECT-STATE-2026-09-23.md`](../docs/PROJECT-STATE-2026-09-23.md).

- **It is a BFF.** The browser never holds the Keycloak token. Client components
  call `/api/proxy/<backend path>`, which forwards with the session's bearer
  token (`app/api/proxy/[...path]/route.ts`). Server components read through
  `lib/api.ts` (`authedGet`, falls back to an empty value when the backend is down).
  A new backend endpoint is called as `/api/proxy/…` from the client; nothing else
  is needed to expose it.
- **Icons are Bootstrap Icons classes** (`<i className="bi bi-eye" />`), from the
  `bootstrap-icons` package. Do not draw SVGs or use emojis. Nav icons are class
  names in `components/Sidebar.tsx`.
- **Shared vocabulary lives in one file each.** Reservation and payment status
  labels/colours and `isEditable`: `components/reservations/reservationStatus.ts`.
  Email languages: `components/reservations/mailLocales.ts`. Suggested deposit
  (display only, the server decides): `components/reservations/paymentSuggest.ts`.
  Form input styles: `inputClass` / `labelClass` in `components/payload/fields.tsx`.
- **Reservation page layout:** status panel → payment panel → edit form (only
  PENDING / CONFIRMED) → staff panel. The status panel mirrors the backend state
  machine to decide which buttons to show; the backend is what enforces it.
- **Never compute money authoritatively here.** Amounts shown or pre-filled are
  estimates; the server recomputes what a client is asked to pay and derives
  payment status from recorded transactions.
- **Keep tables consistent:** reuse `ReservationsTable` (props `limit`,
  `pageSize`, `title`, `canDelete`) rather than building another list.
- **Adding a role-gated action:** the backend's `@PreAuthorize` decides. Handle a
  403 with a toast that names the role limit (see the edit and payment panels).
- Verify with `npm run typecheck -w @dunes/admin` and `npm run lint -w @dunes/admin`
  (root `npm run verify` runs everything).
